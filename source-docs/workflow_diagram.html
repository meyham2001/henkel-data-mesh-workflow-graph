Metadata & governance — applies across all stages

Unity Catalog INSIDE DATABRICKS

Technical metadata, schema, lineage, access enforcement. Stores no data itself. Spans stages 2–9 — it also issues the grants at Stage 9 and produces the lineage DataHub ingests at Stage 8.

DataHub OUTSIDE DATABRICKS

Business glossary, certified definitions, cross-platform discovery. Outside Databricks. Enforces nothing.

Git (Azure DevOps) AUTHORED HEREDEPLOYED TO UC

Data contracts, product specs, pipeline code, CI checks. Git is the system of record; the contract is deployed into Databricks as comments, tags and constraints. Same content, one authority.

Governance function NOT A SYSTEM

Policy, classification taxonomy, the standard definitions must meet. Organisational — a team, not a platform.

“Cross-cutting” here means spans many stages — not outside Databricks. Unity Catalog is inside the platform boundary (and appears again as the nested box below); DataHub is a genuinely separate system; Git is where contracts and pipeline code are authored before deploying into Databricks; governance is a team, not a platform. What they share is that none of them is a step in the flow.

Metadata and governance being split across three systems plus a team is why authority must be assigned explicitly: the same fact held authoritatively in two places is how enforcement and display diverge.

Synapse and Databricks: one-way, not circular. SAP feeds Synapse and Databricks (CIN) independently and in parallel via P47. Separately, Synapse's own modelled output passes into Databricks — one direction only. Databricks does not feed Synapse. Decommissioning therefore means redeveloping the business logic currently inside Synapse, near-source or natively in Databricks, for every product that consumes its modelled output — already an explicit workstream in both of Henkel's documented options (see the version switcher above), not a dependency to untangle.
System placement: Discovery is DataHub (outside Databricks). Consumption is Power BI and applications (outside), with Synapse operating in parallel as an established alternative. Access authorisation is the only stage that straddles the boundary — Unity Catalog issues and enforces grants inside Databricks, while the security service gates frontend consumption outside it. That split is the reason classification-tag authority requires explicit assignment.

System placement: largely unassigned. The components would naturally divide — monitoring and freshness checks as Databricks jobs (inside), impact analysis from Unity Catalog lineage (inside), contract versioning and change policy in Git (outside), alerting into Teams or ServiceNow (outside), and the retirement decision as an organisational one with no system involved. None of this has been assigned. The gap is not only absent capability but an unowned segment of the lifecycle.
